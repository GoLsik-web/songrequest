# Общий Telegram-бот на ПК автора

Бот для стримеров: `@songrequest_streamer_bot`. Поддержка отдельно: `@songrequest_wrapped_bot`.

## Уже реализовано

- Telegram-токен хранится только в Windows Credential Manager автора (`songrequest-common-telegram/bot_token`). Клиентам выдаются отдельные отзываемые ключи привязки, также в хранилище Windows.
- Стример нажимает «Подключить Telegram», открывает одноразовую ссылку (10 минут), нажимает Start в Telegram и подтверждает показанный аккаунт в приложении. До последнего шага управление закрыто.
- Каждое приложение получает только обновления своего владельца. Отправка сообщений другим пользователям запрещена. Для публикации в канал проверяется, что владелец — администратор этого канала.
- Перепривязка отзывает прежнюю копию. `/unlink` и кнопка в приложении отключают привязку. Старые команды управления после перезапуска приложения не выполняются.
- Постоянное WebSocket-соединение для команд, обычные HTTPS-запросы для отправки текста и файлов. Бот не отдаёт клиентам свой Telegram-токен или произвольный доступ к Bot API.
- Локальная очередь команд и курсор Telegram сохраняются в SQLite до подтверждения новых обновлений. Сообщения подключения и уведомления повторяются при временном отказе доставки.

## Запуск автора

1. Установлены проверенные зависимости из `requirements.txt`. Исполняемый помощник собирается командой `go build -ldflags '-H=windowsgui' -o tools/telegram-relay/telegram-relay.exe ./cmd/telegram-relay` из корня проекта.
2. `python configure.py` открывает скрытое поле для токена **общего музыкального бота**. Токен поддержки сюда не подходит. Настройка проверяет имя бота и наличие webhook; чужой webhook не удаляет.
3. После сохранения запускается обработчик на `http://127.0.0.1:8980`. Автозапуск — отдельная запись HKCU Run `SongrequestCommonBot`, без службы Windows и без повышения прав.
4. Проверка `GET /health` показывает имя сервиса и `telegram_online`. `true` означает, что фактический long polling Telegram работает.

Рабочие файлы и журналы — `runtime/`, они исключены из Git. Запись хранилища Windows, `.env` поддержки, базы и сертификаты не включать в ZIP для стримеров.

## Внешний адрес

Пользователь выбрал `bot.zaluplay.online`. До подключения домена приложение можно проверять только на ПК автора через локальный адрес. Сейчас домен обслуживают `ns1.reg.ru`, `ns2.reg.ru`. Обнаружены A-записи корня и `www` на `95.163.244.138`; проверенные MX/TXT отсутствуют, поддомен `bot` отсутствует. Это проверка публичных известных имён, не полный экспорт DNS-зоны.

Для Cloudflare Tunnel потребуется вход пользователя в Cloudflare и проверка/перенос DNS-зоны. Сначала получить полный экспорт записей у REG.RU, импортировать и сверить их; корневые и существующие записи сохранить. Смену NS согласовать по конкретному списку после сверки. Затем создать отдельный Tunnel только для `bot.zaluplay.online → http://127.0.0.1:8980`. Не открывать через него основную панель приложения, другие порты или каталоги.

Используется remotely-managed Tunnel: настройка маршрута в панели Cloudflare, затем локальный `python configure_tunnel.py`. Скопированный токен отдельного туннеля хранится в Windows Credential Manager (`songrequest-common-telegram/tunnel_token`), а не в Git, конфигурации клиента или командной строке. Учётный сертификат Cloudflare с доступом ко всем доменам не нужен. Помощник передаёт токен только дочернему `cloudflared` через окружение. Запуск после входа Windows — отдельная запись HKCU Run `SongrequestTelegramTunnel`, без службы и без открытия портов роутера. Пока токен не введён и DNS не активирован, эта запись не создаётся и внешний доступ не работает.

Для релизной сборки после проверки внешнего HTTPS-адреса:

```powershell
./build.ps1 -Version 0.63.0 -TelegramRelayURL https://bot.zaluplay.online
```

До готовности DNS/туннеля не объявлять удалённое подключение работающим. Пользователь отдельно разрешил публикацию уже сделанного до завершения подключения домена. В релизе необходимо явно указать, что общий бот пока недоступен извне.

## Поддержка при выключенном ПК

Обработчик поддержки находится отдельно в `C:/Projects/kwork-songrequest-bot/songrequest-remote`. Он запускается через HKCU Run `SongrequestSupport`, хранит входящие обновления в `support-inbox.sqlite` до подтверждения Telegram и повторяет неудачную доставку после перезапуска. Уже полученные обращения не удаляются из очереди при временном отказе.

Если ПК автора полностью выключен, новые обращения ожидают на стороне Telegram, где обновления хранятся максимум 24 часа. Без постоянно доступного внешнего обработчика гарантировать сохранность обращений за более долгий офлайн нельзя.

## Проверки

`python -m unittest -v test_relay.py`: изоляция двух пользователей, недопустимые получатели, чужие callback, проверка канала, отзыв/перепривязка, запрет групп, реальный Go-клиент → WebSocket-команды/отчёт/CSV через локальный Python-обработчик. В Go отдельно проверены отсутствие ключа в UI/config, подтверждённый owner ID и запрет небезопасных URL/редиректов.
