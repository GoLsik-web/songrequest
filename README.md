# Заказ музыки для Twitch

Локальное приложение: зрители заказывают треки за баллы канала или донат, а
музыка играет в Spotify самого стримера. Когда очередь заканчивается, Spotify
возвращается ровно туда, где стример остановился.

**Статус: в разработке.** Готовы этапы M0 и M1.
Полная инструкция по установке появится на этапе M7, но подключение Spotify
уже описано отдельно: [docs/Инструкция-Spotify.html](docs/Инструкция-Spotify.html) —
этот файл можно просто переслать стримеру.

## Запуск для разработки

```
go run .                      # запустить
go run . -подробный-лог       # сразу с подробным логом
go run . -без-браузера        # не открывать панель автоматически
go test ./...                 # тесты
```

Панель откроется в браузере на `http://127.0.0.1:8977`.
Настройки, база и лог лежат в `%APPDATA%\songrequest`.

## Сборка релиза

```powershell
.\build.ps1
```

Прогоняет тесты, кладёт `dist\songrequest.exe` и собирает архив с инструкцией
для отправки стримеру. Версия берётся из хеша коммита и видна в панели — по
логу сразу понятно, какая именно сборка стоит у человека.

## Диагностика на расстоянии

Приложение работает у одного человека, а чинит его другой, поэтому:

- в панели каждая ошибка показана с коротким кодом (`SP-04`), который можно
  продиктовать голосом;
- галочка «Подробный лог» включает подробности без перезапуска;
- кнопка «Выгрузить лог» собирает лог, настройки и сведения о системе в один
  `.zip`. Ключи доступа и Client ID из архива вырезаются — это проверяется
  тестом в `internal/diag`.

## Этапы

- [x] **M0** — скелет: локальный сервер, панель, база, настройки, логи
- [x] **M1** — Spotify: вход, снимок состояния и возврат в него
- [ ] **M2** — Twitch: авторизация, награда за баллы, EventSub, возврат баллов
- [ ] **M3** — поиск трека в Spotify по тому, что написал зритель
- [ ] **M4** — очередь, панель целиком, команды в чате
- [ ] **M5** — донаты: DonationAlerts, DonatePay
- [ ] **M6** — фоллбэк на YouTube через yt-dlp и mpv
- [ ] **M7** — виджет для OBS, README для стримера, релиз
